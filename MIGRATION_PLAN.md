## Граница совместимости

`install/db.sql` и `update.inc.php` показывают, что схемы разных выпусков отличаются. Для миграции используется снимок старой БД с правами SELECT, настраиваемыми префиксами данных и пользователей и отдельной целевой MariaDB. Переносится содержимое `strikes`, `stations`, `stations_strikes`, `stations_stat`, `raw`, `user` с исходными ID и временем UTC. Сопоставление учитывает отличие внутреннего ID станции от номера Blitzortung. Старые `conf`, `densities`, `cities`, пользовательские шаблоны и конфигурация сохраняются в снимке. Сериализованный PHP не исполняется. Префиксы, таблицы и обязательные колонки проверяются до записи. Резервная копия служит для аудита и отката.

Замена покрывает прикладные сценарии через новый интерфейс. Растровые PNG/GIF, старые URL и KML, административные PHP-инструменты, произвольные картографические шаблоны, прогнозные треки, уведомления SMS/Twitter/webhook и сторонние загрузки входят в инвентарь, но требуют отдельного переноса при фактическом использовании. Правила обработки данных не позволяют активировать прежние оповещения о грозе. Исторические данные, для которых отсутствуют связи со станциями, остаются доступными в общем архиве.

## Порядок

1. Зафиксировать исходники, формат файлов, обязательные поля и правила доступа.
2. Реализовать схему, перенос и CLI. Проверить сверку строк, ссылки, UTC, повторный запуск и восстановление после ошибки.
3. Реализовать worker и проверить разбор журналов, gzip, HTTP-ошибки, опоздавшие разряды и повторный импорт.
4. Реализовать API и интерфейс. Проверить сессии, права, карту, фильтры архива, статистику, настройки и оба языка.
5. Проверить Compose, MariaDB и Nginx на стенде. Сравнить контрольный период и несколько станций на копии реальной БД. Перед переключением остановить PHP cron, снять финальную копию, повторить сверку и затем включить новый worker. При откате остановить worker, вернуть upstream и cron PHP, сохранить целевую БД с данными, принятыми после переключения.

## Доступ и лицензии

Исходный код распространяется на условиях GPL-3.0-or-later. Отдельные уведомления и условия ресурсов остаются в `legacy/`. Участники и получившие разрешение лица используют авторизованный серверный импорт. По умолчанию он выключен. Карта недавних разрядов и её API открыты без входа; архив, станции и статистика требуют учётную запись. Условия источника описаны в [Blitzortung.org](https://www.blitzortung.org/en/contact.php). Подтверждение доступа и разрешённой аудитории входит в приёмку установки.

## Результаты проверки

- Исходные 197 файлов в `legacy/` сверены с зафиксированным коммитом.
- Тесты покрывают атомарный перенос, отказ при непустой цели, сохранение ID и наносекунд, обновление MD5-хэша, права, архив, графики, настройки и повтор импорта.
- На MariaDB 11.4.13 проверены перенос из схемы `install/db.sql`, транзакции импорта и чтение результатов через API.
- Сквозной тест в Chrome через Nginx проверил путь `/mybo/`, оба языка, карту на широком и узком экране, архив, плотность, сохранённый сигнал, график станции и настройки.
- Конфигурация Compose прошла `docker compose config`. Полный запуск контейнеров входит в GitHub Actions и приёмку на Ubuntu.
- Перед переключением установки требуется сверка на снимке её БД и пробный цикл с разрешённым потоком Blitzortung. Автоматические тесты импорта используют локальные файлы и имитацию HTTP. Загрузка осциллограмм с отдельного сервера сигналов пока остаётся в PHP. Python показывает сигналы, сохранённые в мигрированной БД.

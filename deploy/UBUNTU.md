# Развёртывание на Ubuntu Server

## Первичная установка через install.sh

Откройте терминал в папке полной копии проекта, где находятся `compose.yaml`, `.env.example` и `deploy/install.sh`. На сервере должен быть установлен Python 3. Запустите:

```bash
sudo bash deploy/install.sh
```

1. Выберите `1` для доступа по публичному IP через HTTP или `2` для домена через HTTPS.
2. При выборе IP введите публичный IPv4 и откройте TCP-порт `8080` в панели хостинга. Для домена заранее настройте DNS на этот сервер и откройте TCP-порты `80` и `443`; введите домен без схемы и пути, затем email для сертификата Let's Encrypt.
3. Дождитесь установки Docker и Compose, сборки образа и запуска контейнеров. Для HTTPS скрипт также установит Nginx и Certbot, настроит прокси и сертификат.
4. Если пользователей сайта ещё нет, задайте логин администратора (по умолчанию `operator`) и пароль длиной не менее 12 символов.
5. Откройте адрес из строки `Open:` и войдите с этой учётной записью.

Не нужно заранее копировать `.env.example`: при отсутствии `.env` скрипт создаёт его сам и генерирует пароли базы. Импорт Blitzortung остаётся выключенным до настройки в разделе «Импорт и эксплуатация».

Проверьте результат:

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 api worker
curl -fsS http://127.0.0.1:8080/health/ready
```

Для обычной установки через скрипт разделы 1–3 ниже выполнять не требуется. Они предназначены для ручной настройки, существующего Nginx и установки по подпути. При переносе старой PHP-базы используйте ручной сценарий с разделом миграции до создания пользователя и запуска API.

## Повторный запуск install.sh

После размещения обновлённых файлов в папке проекта можно повторить `sudo bash deploy/install.sh`. Он снова запросит IP или домен, пересоберёт приложение и сохранит базу, пользователей, пароли и настройки импорта. Администратор повторно не создаётся, если в базе уже есть пользователи.

Скрипт заново задаёт адрес сайта, пустой `MYBO_BASE_PATH`, порт `8080`, адрес привязки API и режим cookie в `.env`; в режиме HTTPS также перезаписывает конфигурацию сайта MyBlitzortung в Nginx. Для обычного перезапуска или обновления с сохранением собственной настройки адресов используйте [команды Compose в README](../README.md#перезапуск-и-применение-изменений).

В командах Docker ниже добавляйте `sudo`, если пользователь не имеет доступа к Docker.

## 1. Подготовка

Понадобятся Docker Engine с Compose v2, работающий Nginx и HTTPS-сертификат для сайта. Установите Docker и плагины по инструкции для своей версии Ubuntu. [Docker Engine на Ubuntu](https://docs.docker.com/engine/install/ubuntu/).

```bash
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
openssl rand -hex 32
```

Запишите разные сгенерированные пароли в `MARIADB_ROOT_PASSWORD` и `MARIADB_PASSWORD`. Установите `MYBO_ORIGIN` в точный публичный origin, например `https://lightning.example.org`, без пути, и `MYBO_SECURE_COOKIE=true`. Для `https://example.org/mybo/` используйте `MYBO_ORIGIN=https://example.org` и `MYBO_BASE_PATH=/mybo`. MariaDB доступна внутри сети Compose. По умолчанию API публикует порт `8080` на всех интерфейсах; ограничьте доступ сетевым экраном либо настройте HTTPS-прокси. Для доступа только с этого компьютера можно привязать порт к `127.0.0.1`.

```bash
docker compose config --quiet
docker compose up -d --build db init
docker compose ps -a
```

Сервис `init` должен завершиться с кодом 0. Для существующей установки выполните раздел миграции ниже перед созданием администратора и стартом API.

## 2. Создание администратора и запуск

```bash
docker compose run --rm init python -m mybo.cli create-admin operator
docker compose up -d api worker
docker compose ps
curl -fsS http://127.0.0.1:8080/health/ready
```

CLI интерактивно запросит отдельный пароль длиной от 12 символов. Для аварийного административного входа можно задать отдельные `MYBO_SUPERADMIN_LOGIN` и `MYBO_SUPERADMIN_PASSWORD` в `.env`; оба значения обязательны, а пароль должен содержать от 12 до 256 символов. Эта пара не связана с Blitzortung и получает все права сайта. Её изменение с перезапуском API аннулирует прежние сессии суперадминистратора. Сессии хранятся в БД и действуют 12 часов. Администратор создаёт пользователей в настройках, даёт право на архив и право менять настройки отображения. Других локальных администраторов создаёт оператор через CLI. Развёртывание с HTTP на локальном тестовом стенде требует выставить `MYBO_SECURE_COOKIE=false` и соответствующий `http://...` в `MYBO_ORIGIN`.

## 3. Существующий Nginx

Скопируйте `nginx-rate.conf` в каталог, подключаемый из `http {}`, а `nginx-proxy-common.conf` в `/etc/nginx/snippets/mybo-proxy-common.conf`. В существующем HTTPS-блоке `server {}` используйте содержимое `nginx-proxy.conf` для отдельного домена или `nginx-subpath.conf` для пути. В варианте с путём сохраните префикс URI при проксировании, оставив `proxy_pass` без завершающего `/`. При выборе другого порта или пути синхронизируйте его с `.env` и обоими конфигами Nginx. [Семантика proxy_pass](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass).

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -fsS https://lightning.example.org/health/ready
# Или для установки по пути:
curl -fsS https://example.org/mybo/health/ready
```

После входа проверьте карту, архив и статистику. Публичный запрос к `/api/strikes/live` под тем же префиксом должен возвращать 401. Пример Nginx ограничивает попытки входа по IP. Если Nginx стоит за другим прокси, используйте существующую доверенную конфигурацию Real IP.

## 4. Миграция PHP

1. Создайте отдельный снимок старой БД. Для окончательного снимка остановите PHP cron и другие записи. Сохраните `config.php`, старый код, пользовательские ресурсы и дамп в защищённом месте. При MyISAM согласованность требует, чтобы во время дампа никто не записывал данные.
2. Восстановите дамп в отдельную БД, например `mybo_legacy`. Создайте для миграции отдельного пользователя с правом `SELECT` на неё. Если снимок находится в MariaDB Compose, используйте `LEGACY_HOST=db`. Параметры из `config.php` переносите вручную по таблице ниже.
3. Оставьте сервисы API и worker остановленными и проверьте, что новая схема создана, а прикладные таблицы пусты. В Bash задайте параметры источника. Пароль введите без эха и передайте по имени переменной.

```bash
export LEGACY_HOST=db LEGACY_USER=mybo_reader LEGACY_DATABASE=mybo_legacy
read -rsp 'Legacy database password: ' LEGACY_PASSWORD; printf '\n'
export LEGACY_PASSWORD

docker compose run --rm \
  -e LEGACY_HOST -e LEGACY_USER -e LEGACY_DATABASE -e LEGACY_PASSWORD \
  init python -m mybo.cli migrate-legacy --prefix bo_ --check

docker compose run --rm \
  -e LEGACY_HOST -e LEGACY_USER -e LEGACY_DATABASE -e LEGACY_PASSWORD \
  init python -m mybo.cli migrate-legacy --prefix bo_

unset LEGACY_PASSWORD
```

Если у таблицы пользователей свой префикс, добавьте `--user-prefix` в обе команды. Для нестандартного порта передайте `-e LEGACY_PORT=...`. Команда с `--check` проверяет таблицы, колонки и считает строки. Основная команда переносит шесть таблиц в одной транзакции и сверяет количества. Старый пользователь с ID 1 был связан с учётной записью Blitzortung и пропускается. Остальные ID, уровни доступа и почта сохраняются, локальные MD5-хэши обновляются до Argon2id при первом успешном входе. При ошибке транзакция откатывается. Повтор после ошибки допустим при пустых целевых таблицах. Повтор после успеха останавливается с ошибкой, защищая от наложения двух снимков.

| Старый параметр | Где задать |
| --- | --- |
| `BO_USER`, `BO_PASS`, `BO_REGION`, `BO_IMPORT_SERVER` | `BO_FEED_USER`, `BO_FEED_PASSWORD`, `BO_FEED_BASE` с корректным регионом и HTTPS |
| `BO_STATION_ID` | `BO_OWN_STATION` с номером в сети Blitzortung |
| `BO_LAT`, `BO_LON`, `BO_RADIUS` | `MYBO_SITE_LAT`, `MYBO_SITE_LON`, `MYBO_VIEW_RADIUS_KM` для ограничения координат. Для старой настройки по умолчанию используйте 50 км |
| Центр и масштаб карты, имя сайта, язык, окно отображения | Настройки интерфейса |
| `BO_UP_INTVL_STRIKES`, `BO_UP_INTVL_STATIONS` | `BO_POLL_SECONDS`, `BO_STATION_SECONDS` в секундах |

Ограничение радиуса применяется к данным разрядов, архиву, плотности, осциллограммам и графику количества разрядов для пользователей без прав администратора или прежнего `BO_PERM_NOLIMIT`. Исторические суммарные показатели станций берутся из `stations_stat`. Проверьте область просмотра и разрешения локальных пользователей до запуска сайта. Новое приложение показывает время в UTC.

На тестовой копии сравните число разрядов за контрольный период, выборку с одинаковой секундой и разными наносекундами, список станций и их почасовые ряды, один сохранённый сигнал и права нескольких аккаунтов. После проверки сделайте окончательный перенос на пустую целевую БД. Для отката остановите Python worker, верните прежний upstream в Nginx и запустите PHP cron. Сохраните новую MariaDB, чтобы отделить данные, полученные после переключения. Снимок PHP остаётся самостоятельным.

## 5. Импорт и эксплуатация

Перезапуск приложения, пересборка после изменения кода и применение `.env` описаны в [README: «Перезапуск и применение изменений»](../README.md#перезапуск-и-применение-изменений). После обновления карты или других файлов сайта выполните из папки проекта:

```bash
docker compose up -d --build --force-recreate api worker
docker compose ps
docker compose logs --tail=100 api worker
```

Затем принудительно обновите страницу браузера (`Ctrl+Shift+R`, на macOS — `Cmd+Shift+R`).

Проверьте в закрытом Compendium участника точный адрес региона, разрешённые интервалы опроса и условия доступа. Укажите в `.env` разрешённую HTTPS-базу, логин, пароль и номер собственной станции. Включите `BO_IMPORT_ENABLED=true`, затем пересоздайте worker, чтобы применить учётные данные импорта.

```bash
docker compose up -d --build --force-recreate worker
docker compose logs --tail=100 worker
docker compose exec worker python -m mybo.worker --health
```

Worker читает `Strokes/YYYY/MM/DD/HH/MM.log` и `stations.txt.gz`. По умолчанию начальная загрузка охватывает два часа. После остановки worker догоняет сохранённый курсор и перепроверяет открытые интервалы. Ответы 404 для закрытых интервалов отмечаются в журнале и пропускаются. Если провайдер позже восстановит такой файл или изначально нужен более глубокий архив, выполните ручную загрузку разрешённой копии. HTTP 401/403 и несовместимый формат дают диагностическую запись и оставляют соответствующую операцию для повтора. На серверы Blitzortung обращается только worker.

```bash
docker compose run --rm -v /srv/mybo-import:/input:ro -e BO_OWN_STATION \
  init python -m mybo.cli import-file strikes /input/authorized.log
docker compose run --rm -v /srv/mybo-import:/input:ro \
  init python -m mybo.cli import-file stations /input/stations.txt.gz
```

Файлы импортируются транзакционно. Повтор файла безопасен. Остановите worker перед продолжительной ручной дозагрузкой, если он удерживает блокировку. Карта и архив сохраняют статистику и события в постоянном томе `database`. Планируйте объём диска и регулярно делайте резервную копию. Секреты из `.env` храните отдельно от дампа.

```bash
umask 077
docker compose exec -T db sh -c \
  'mariadb-dump --single-transaction --quick -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE"' \
  > "mybo-$(date +%F).sql"
```

Для восстановления используйте пустую проверочную БД с заранее созданным пользователем. После загрузки дампа проверьте наличие записей и вход. Обновление контейнеров сохраняет именованный том. Административные обновления БД и восстановление сначала проверяйте на копии. `docker compose down -v` удаляет том.

По умолчанию используется локальная карта Natural Earth. Для детальной подложки можно установить `MYBO_TILE_URL` с `{z}/{x}/{y}` и `MYBO_TILE_ATTRIBUTION`. При использовании публичных тайлов OSM соблюдайте ограничения их сервиса. [Политика тайлов OSM](https://operations.osmfoundation.org/policies/tiles/).

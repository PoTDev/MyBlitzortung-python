# MyBlitzortung на Python

MyBlitzortung показывает недавние молнии на карте Leaflet, ищет разряды по времени, области и станции, строит графики сети и станций и отображает сохранённые формы и спектры сигналов. Интерфейс доступен на русском и английском.

Главная карта недавних разрядов открыта без входа. Архив, список станций, статистика, сохранённые сигналы, настройки и управление пользователями требуют учётную запись MyBlitzortung. Кнопка регистрации в шапке ведёт на официальный сайт Blitzortung.org; аккаунты Blitzortung и MyBlitzortung не связаны автоматически, поскольку у Blitzortung нет опубликованного OAuth для сторонних сайтов.

Станции на карте по умолчанию скрыты. Авторизованный пользователь может включить их вручную галочкой «Станции»; при следующем входе слой снова будет выключен.

| Компонент | Назначение |
| --- | --- |
| `mybo/api.py` | FastAPI, сессии, архив, статистика, настройки, управление учётными записями |
| `mybo/worker.py`, `mybo/feed.py` | Фоновая загрузка защищённых журналов и снимков станций |
| `mybo/db.py`, `mybo/migration.py` | Схема SQLAlchemy, MariaDB, перенос из PHP |
| `web/` | Отдельный статический интерфейс на Leaflet, который API раздаёт на том же origin |
| `legacy/` | Полная копия исходного MyBlitzortung 1.4-dev7 и его уведомлений о лицензиях |

## Локальный запуск без домена

Docker и MariaDB для локального запуска не нужны: используется SQLite, а сайт открывается по адресу `http://127.0.0.1:8000`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export MYBO_DATABASE_URL=sqlite:///./mybo.sqlite3
export MYBO_ORIGIN=http://127.0.0.1:8000
export MYBO_SECURE_COOKIE=false
.venv/bin/python -m mybo.cli init-db
.venv/bin/python -m mybo.cli create-admin operator
.venv/bin/uvicorn mybo.api:create_app --factory --host 127.0.0.1 --port 8000
```

Команда создания администратора запросит пароль длиной не менее 12 символов. Откройте `http://127.0.0.1:8000` и войдите под созданной учётной записью. Для доступа с другого устройства задайте `MYBO_ORIGIN` равным точному HTTP-origin с IP-адресом сервера и портом, а сервер запускайте с `--host 0.0.0.0`; не публикуйте такой HTTP-доступ в недоверенную сеть.

## Запуск в Docker на сервере

Все команды выполняйте в терминале из папки проекта, где находится `compose.yaml`. При доступе по IP сайт открывается по адресу `http://IP_СЕРВЕРА:8080`.

### Первичная установка через install.sh

На Ubuntu Server откройте папку проекта с `compose.yaml` и запустите установщик:

```bash
sudo bash deploy/install.sh
```

Python 3 должен быть установлен на сервере: скрипт использует его для проверки параметров ещё до установки Docker.

1. Выберите способ доступа: `1` — публичный IP и HTTP, `2` — домен и HTTPS.
2. Для варианта `1` введите публичный IPv4 сервера и разрешите входящий TCP-порт `8080` в панели хостинга. Для варианта `2` заранее направьте DNS домена на сервер, откройте TCP-порты `80` и `443`, затем введите домен без `https://` и email для Let's Encrypt.
3. Установщик создаст `.env`, если его ещё нет, сгенерирует пароли базы, установит Docker и Compose, соберёт и запустит контейнеры. В режиме HTTPS он также установит и настроит Nginx и сертификат.
4. Если в базе ещё нет пользователей сайта, введите логин первого администратора (по умолчанию `operator`) и пароль длиной не менее 12 символов. Повторно создавать этого пользователя отдельной командой не нужно.
5. Откройте адрес из строки `Open:`: `http://IP_СЕРВЕРА:8080` или `https://ваш-домен`. Войдите с созданной учётной записью.

После установки проверьте состояние контейнеров:

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 api worker
```

Для следующих команд `docker compose` используйте `sudo`, если текущий пользователь не имеет доступа к Docker. Импорт разрядов по умолчанию выключен; его настройка описана в разделе «Получение данных своей учётной записи Blitzortung» ниже. Подробности ручной установки и переноса старой базы — в [руководстве Ubuntu](deploy/UBUNTU.md).

Карта в Docker использует встроенную однотонную подложку Natural Earth с границами стран. При приближении появляются границы областей и подписи крупных городов на выбранном языке интерфейса (русском или английском). Она работает локально и не требует внешнего поставщика тайлов. При необходимости можно задать поддерживаемый HTTPS-поставщик в `.env`.

По умолчанию включена светлая тема; переключатель в верхней панели включает тёмную, а выбор сохраняется в браузере. В разделе «Станции» кнопка «Увеличить» разворачивает любой график, в том числе диаграмму направлений, в отдельное большое окно.

Для выбранной станции отображаются текущая скорость сигналов и подтверждённых разрядов, примерная эффективность, доля обнаружения в радиусах 100–1000 км, распределение дальности и профиль активности по часам UTC. Все географические показатели рассчитываются от координат выбранной станции; они работают для любой станции из базы.

Запустить контейнеры или проверить их состояние:

```bash
docker compose up -d
docker compose ps
```

При ручной установке создать администратора сайта (если ещё не создавали):

```bash
docker compose run --rm init python -m mybo.cli create-admin operator
```

Задайте пароль длиной не менее 12 символов. Это пароль **только для входа в MyBlitzortung**. Затем откройте сайт в браузере и войдите с логином `operator` и этим паролем.

### Перезапуск и применение изменений

Выполняйте команды из папки проекта с `compose.yaml` и `.env`.

Для повторного выполнения установки, включая настройку доступа по IP или домену, можно снова запустить:

```bash
sudo bash deploy/install.sh
```

Скрипт использует файлы текущей копии проекта; сначала поместите в неё обновлённый код. Снова выберите способ доступа и введите IP или домен. Он пересоберёт и запустит приложение, сохранит базу, пользователей, пароли и параметры импорта. При этом заново запишет `MYBO_ORIGIN`, `MYBO_BASE_PATH` (пустое значение), `MYBO_BIND_HOST`, `MYBO_BIND_PORT` (`8080`) и `MYBO_SECURE_COOKIE`. В режиме HTTPS он также перезапишет конфигурацию сайта MyBlitzortung в Nginx. Для установки по подпути или с собственными настройками прокси используйте команды Compose ниже.

После изменения кода, карты, файлов `web/`, зависимостей или `Dockerfile` пересоберите образ и пересоздайте контейнеры приложения:

```bash
docker compose up -d --build --force-recreate api worker
docker compose ps
docker compose logs --tail=100 api worker
```

Файлы сайта копируются внутрь образа при сборке, поэтому обычный `restart` не применяет изменения этих файлов. После обновления выполните принудительное обновление страницы в браузере (`Ctrl+Shift+R`, на macOS — `Cmd+Shift+R`). База данных и учётные записи сохраняются в именованном томе.

Для обычного перезапуска приложения без изменения кода и `.env`:

```bash
docker compose restart api worker
```

После изменения только `.env` пересоздайте контейнеры, чтобы они получили новые значения:

```bash
docker compose up -d --force-recreate api worker
```

Для перезапуска всех работающих сервисов, включая базу данных:

```bash
docker compose restart
```

При локальном запуске без Docker остановите Uvicorn сочетанием `Ctrl+C` и снова выполните команду запуска из раздела «Локальный запуск без домена».

### Развёртывание сайта на домене с HTTPS

Нужен собственный домен, который вы контролируете. В примерах замените `lightning.example.org` на свой домен. Записи DNS `A` должны указывать на IP сервера; открытые входящие порты TCP `80` и `443` нужны для получения сертификата и HTTPS. Если у домена есть запись `AAAA`, она тоже должна указывать на этот сервер и быть доступна извне.

1. Установите Nginx и Certbot на Ubuntu, если они ещё не установлены:

   ```bash
   sudo apt update
   sudo apt install -y nginx certbot python3-certbot-nginx
   ```

2. В файле `.env` проекта укажите домен, HTTPS-cookie и закройте порт приложения от прямого доступа из интернета:

   ```dotenv
   MYBO_ORIGIN=https://lightning.example.org
   MYBO_SECURE_COOKIE=true
   MYBO_BASE_PATH=
   MYBO_BIND_HOST=127.0.0.1
   MYBO_BIND_PORT=8080
   ```

   Сохраните остальные значения `.env`, в том числе пароли базы данных и Blitzortung. Не создавайте `.env` заново и не удаляйте Docker volume: в нём находятся база и пользователи сайта.

3. Скопируйте настройки ограничения частоты входа и общий proxy-snippet из папки проекта:

   ```bash
   cd /путь/к/MyBlitzortung
   sudo cp deploy/nginx-rate.conf /etc/nginx/conf.d/mybo-rate.conf
   sudo cp deploy/nginx-proxy-common.conf /etc/nginx/snippets/mybo-proxy-common.conf
   ```

4. Создайте начальный файл сайта Nginx, заменив домен в `server_name`:

   ```bash
   sudo tee /etc/nginx/sites-available/mybo >/dev/null <<'EOF'
   server {
       listen 80;
       server_name lightning.example.org;
       location / { return 404; }
   }
   EOF
   sudo ln -s /etc/nginx/sites-available/mybo /etc/nginx/sites-enabled/mybo
   sudo nginx -t
   sudo systemctl reload nginx
   ```

5. Получите TLS-сертификат и включите автоматический редирект HTTP → HTTPS:

   ```bash
   sudo certbot --nginx -d lightning.example.org
   ```

   Следуйте подсказкам Certbot и выберите перенаправление HTTP на HTTPS, если он предложит выбор.

6. Откройте `/etc/nginx/sites-available/mybo`. В созданный Certbot блок `server` для HTTPS вставьте содержимое файла `deploy/nginx-proxy.conf` из проекта. Он перенаправит запросы на локальный Docker-порт. Проверьте конфигурацию и примените её:

   ```bash
   sudo nginx -t
   sudo systemctl reload nginx
   ```

7. Пересоздайте API-контейнер с новым origin и привязкой порта к localhost:

   ```bash
   cd /путь/к/MyBlitzortung
   docker compose config --quiet
   docker compose up -d --force-recreate api
   docker compose ps
   curl -fsS https://lightning.example.org/health/ready
   ```

   Откройте `https://lightning.example.org`. Учётные записи и пароль администратора останутся прежними. После переезда вход через старый IP-адрес работать не должен из-за проверки origin и cookie; используйте домен. Конфигурация Nginx также доступна в [инструкции развёртывания](deploy/UBUNTU.md).

### Получение данных своей учётной записи Blitzortung

Серверный worker получает защищённые файлы по HTTPS с учётными данными и адресом потока, на использование которых у оператора есть разрешение. Обычный логин сайта Blitzortung сам по себе такого доступа не гарантирует. Форма входа MyBlitzortung не настраивает импорт.

Данные потока `BO_FEED_USER` / `BO_FEED_PASSWORD` используются только worker и не дают доступа к сайту. Для аварийного административного входа можно задать в `.env` отдельную пару `MYBO_SUPERADMIN_LOGIN` / `MYBO_SUPERADMIN_PASSWORD`; пароль должен содержать от 12 до 256 символов. Суперадминистратор получает все права, а смена этой пары с перезапуском API прекращает действие его прежних сессий. Локальные пользователи и администраторы из базы продолжают работать.

На форме входа есть ссылка на официальную регистрацию Blitzortung.org. Сама регистрация выполняется на стороне Blitzortung через ссылку в веб-интерфейсе контроллера станции. Blitzortung не предоставляет опубликованного OAuth/API для передачи подтверждённого входа стороннему сайту, поэтому аккаунт Blitzortung нельзя использовать как универсальный вход в MyBlitzortung.

1. Проверьте в закрытом Compendium участника Blitzortung, разрешён ли доступ к защищённому потоку, точный HTTPS-адрес для вашего региона и допустимую частоту запросов. Если доступа или адреса нет, оставьте импорт выключенным и обратитесь к Blitzortung.
2. Откройте файл `.env` в папке проекта. Внесите полученные для потока значения:

   ```dotenv
   BO_IMPORT_ENABLED=true
   BO_FEED_BASE=https://data.blitzortung.org/Data_1/Protected
   BO_FEED_USER=выданное_для_потока_имя
   BO_FEED_PASSWORD=выданный_для_потока_пароль
   BO_OWN_STATION=0
   ```

   Используйте адрес региона и учётные данные, указанные для вашего доступа; пример адреса не обязательно подходит вашей учётной записи. Вместо `0` укажите ID своей станции из Blitzortung, если он известен. Не публикуйте `.env`, не вставляйте пароль в чат и ограничьте доступ к файлу:

   ```bash
   chmod 600 .env
   ```

3. Пересоздайте worker, чтобы применить учётные данные импорта, и проверьте журнал:

   ```bash
   docker compose up -d --build --force-recreate worker
   docker compose logs --tail=100 worker
   ```

   Сообщение `Blitzortung import enabled` означает, что worker запущен с включённым импортом, но не гарантирует успешный доступ к потоку. Ошибки 401/403 обычно означают, что сервер не разрешает доступ с указанными адресом или учётными данными. Не пытайтесь обходить ограничение; уточните параметры у Blitzortung. Импорт выключен по умолчанию.

Пароль локального администратора и пароль суперадминистратора сайта задаются отдельно от пароля потока Blitzortung. При доступе к сайту по обычному HTTP пароль входа не шифруется; для публичного сервера настройте HTTPS.

### График направлений своей станции

Если в `.env` задан `BO_OWN_STATION`, например `3211`, приложение выберет эту станцию по умолчанию во вкладке **«Станции»**. Там можно выбрать период и посмотреть круговую диаграмму направлений. Она показывает географические азимуты от координат станции к разрядам, в обнаружении которых участвовала станция. Это не измерение направления антенной и не «пеленг» радиосигнала. Для расчёта нужны координаты станции и записи разрядов, полученные worker.

## Автоматические проверки

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Основные тесты используют временные БД SQLite и имитацию HTTP-ответов. Интеграционный тест использует схему исходного `legacy/install/db.sql` и требует **две пустые тестовые БД MariaDB**. Имена обеих БД должны заканчиваться на `_test`. Укажите `MYBO_TEST_DB_URL` и `MYBO_TEST_LEGACY_URL` в формате SQLAlchemy `mysql+pymysql://...`. В GitHub Actions эти БД создаются автоматически.
